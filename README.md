# Language Tutor in YouTube

Chrome 擴充功能。觀看 YouTube 影片時，每播放約 30 秒於句尾自動暫停，整理該段的單字、片語與文法重點，
並提供逐句複習（單句重播、0.75× 慢速跟讀、聽寫模式）。複習完畢後按「繼續」即可接著播放下一段。

分析由使用者自備的 API key 執行，可在設定頁選擇 **Claude（Anthropic）** 或 **Gemini（Google）**。

本擴充免費、開放原始碼、無廣告，且不蒐集任何資料（見 [PRIVACY.md](PRIVACY.md)）。

## 功能

- **自動分段暫停**：於句尾暫停並整理該段內容，可隨時切換為連續播放。
- **逐句複習**：點選任一句即重播該句；支援 0.75× 慢速、顯示／隱藏翻譯，以及聽寫模式（先遮蔽原文，點選該句後揭曉）。
- **框選解說**：在原文上選取句中的一個片段，即可詢問該片段在這句話裡的意思，或單獨收藏。
- **收藏與匯出**：單字、片語、句子與文法重點皆可收藏，並跨影片保存於生字本。可匯出為 Anki 可直接匯入的 CSV，
  或供 Excel／Numbers 開啟的詳細表格。
- **日文假名標註**：學習語言為日文時，逐句複習、單字與片語的漢字上方會標註平假名（如 `速(はや)すぎて`）。
- **單字發音**：單字與片語卡片上的 🔊 使用瀏覽器內建語音合成，不需額外權限，亦不會連外。
- **背景預先整理**：觀看第 N 段時，背景會先整理第 N+1 段，使暫停時可立即開始複習。
- **十種學習語言**：法文、英文、日文、韓文、西班牙文、德文、義大利文、葡萄牙文、中文、俄文。
- **預設不自動執行**：必須由使用者在該影片上啟動，才會讀取字幕與呼叫 API。

## 設計取向

多數同類工具採用「雙字幕加點字查詢」，使用者需於聆聽途中停下處理單一詞彙。
本擴充改為**先完整聽完一段，再一次整理**：播放中的約 30 秒為連續的聽力輸入，暫停後才進行學習。

整段一併分析也使輸出內容不同於單字查詢：除單字外，還包含整句的結構與母語者的慣用說法，
這些資訊只存在於句子層級。

此取向有以下代價：

- 每個段落需呼叫一次 API，成本高於純字典查詢。為此提供結果快取（同一段不重複計費）與預先整理（見上）。
- 想立即得知單一詞彙意思時，速度較慢。框選解說用於補足此情境，其回答仍以整句語境為基礎，而非字典定義。

## 安裝

**從 Chrome 線上應用程式商店安裝**：搜尋「Language Tutor in YouTube」。

**從原始碼安裝**：

1. 開啟 `chrome://extensions`。
2. 開啟右上角「開發人員模式」。
3. 點選「載入未封裝項目」，選擇本專案資料夾。

**初次設定**：

1. 點選工具列的擴充功能圖示開啟設定頁（在非影片頁面點選圖示會直接開啟設定頁）。
2. 選擇 AI 供應商，填入對應的 API key 與模型。尚無 API key 者，可展開「第一次用？」的圖文教學，依步驟申請：
   - Claude：於 [console.anthropic.com](https://console.anthropic.com) 申請。須先儲值，無免費額度。
   - Gemini：於 [aistudio.google.com](https://aistudio.google.com/apikey) 申請。提供免費額度，不需綁定信用卡，但有用量上限。
3. 選擇學習語言並儲存，可用「測試 API key」確認金鑰有效。
4. 開啟任一支有字幕的 YouTube 影片，面板會顯示於右側欄最上方。

為維持介面精簡，下列項目使用固定預設值，設定頁不提供調整：每段長度（約 30 秒）、解釋語言（繁體中文）、
自動暫停（開啟）、自動啟動（關閉）、Anki 匯出格式（兩欄）。

## 使用方式

- **啟動與結束**：按面板上的「開始學習這部影片」，或點選工具列圖示。啟動中的分頁，圖示會顯示 `ON`。
  按面板標頭的 ⏹ 或再次點選圖示即結束。
- **自動暫停**：播至段落結尾時自動暫停並整理。面板右上角的「⏸ 自動停／▶ 連續播」可隨時切換。
- **逐句複習**：點選任一句即重播；`0.75×` 為慢速跟讀。
- **顯示翻譯／聽寫模式**：兩個獨立開關。聽寫模式會先模糊原文，點選該句後才揭曉。
- **假名標註**：學習語言設為日文時自動標註，其他語言不受影響。
- **🔊 聽發音**：單字與片語卡片上的 🔊 為合成音。句子沒有這顆按鈕——點選句子即會跳回影片聽原聲，真人語調優於合成音。
- **框選片段**：在原文那一行選取一段文字，會出現「💡 解說」與「★ 收藏這段」。
  適用於只想記住長句中的某個子句，或只有某個結構看不懂的情況。
- **★ 收藏**：句子、單字、片語、文法重點皆可收藏，再點一次即取消。收藏內容保存於生字本，跨影片累積。
  句子會匯出為 Anki 的句子卡（正面為原文，背面為翻譯）。
- **匯出**：複習畫面底部可隨時匯出目前的收藏，不必等影片播完。設定頁亦可匯出整份生字本。
- **完成畫面**：影片播畢後顯示該部影片的統計，並可匯出收藏或全部內容。

## 專案架構

| 檔案 | 作用 |
|---|---|
| `content/bridge.js` | 執行於頁面主世界（MAIN world），讀取 YouTube 的 `getPlayerResponse()` 取得字幕軌清單，並向播放器取得字幕網址 |
| `content/transcript.js` | 取得字幕與語言檢查；以播放器路徑為主，轉錄稿面板 DOM 為備援 |
| `content/segmenter.js` | 字幕切段（優先句尾，其次最接近設定秒數），以及句子與時間的對應 |
| `content/app.js` | 監聽 `timeupdate`，處理暫停、單句播放與整體流程 |
| `content/panel.js`、`panel.css` | 右側面板介面（側欄被隱藏時改為浮動面板） |
| `background/providers.js` | Claude／Gemini 的請求與回應解析（與測試頁共用同一份） |
| `background/service-worker.js` | 呼叫 API（content script 受 CORS 限制，無法直接請求）與結果快取 |
| `shared/anki.js` | 匯出 CSV（Anki 匯入檔與詳細表格），由面板與設定頁共用 |
| `options/` | 設定頁（含生字本的匯出與清除、快取清除），以及 API key 申請的圖解步驟圖（`options/guides/`） |
| `icons/` | 工具列與商店圖示 |

`shared/anki.js` 另保留分欄格式（`toFieldsCsv`）與其測試，目前設定頁未提供切換。

| `test/furigana-test.js` | 日文假名的切分對齊與語音挑選（純函式） |

`test/harness.js` 將 `chrome`、DOM 與面板替換為 stub，使實際的 content script 能在 Node 中執行，
並提供可手動推進時間的假 `<video>`。

測試一律**載入實際的程式碼，而非另寫副本**。曾發生面板呼叫 `exportCsv('starred')`，
而 `exportCsv` 並未宣告該參數的情況：兩側各自正確，語法檢查亦通過，功能卻失效。
此類介面不一致只有在實際串接執行時才會被發現。

無法在 Node 中測試的部分（面板外觀、YouTube 的 DOM、真實 API 呼叫）使用以下手動工具：

```bash
python3 -m http.server 8731
# test/panel-preview.html  檢視面板各種狀態的外觀
# test/api-test.html       填入 API key 發出一次真實請求，檢視輸出品質
```

## API 與費用

| 供應商 | 端點 | 可選模型 |
|---|---|---|
| Claude | `api.anthropic.com/v1/messages` | Opus 5.5（預設）、Sonnet 5.5、Haiku 5.5 |
| Gemini | `generativelanguage.googleapis.com/v1beta/interactions` | 3.5 Flash-Lite（預設）、3.8 Flash、4 Hydrogen |

- 兩個供應商的 key 與模型各自保存，可隨時切換。
- 兩者共用同一份 JSON Schema 約束輸出：Claude 使用 `output_config.format`，Gemini 使用 `response_format`。
- Gemini 已於 2026/05 改用 Interactions API（舊的 `generateContent` 列為 legacy）。
  請求不送 `Api-Revision` 標頭：`steps[]` 回應格式已是預設，且 Google 的 CORS 不放行該標頭；
  回應解析同時支援新舊兩種格式。
- 若帳號或模型不支援結構化輸出參數，請求會逐步降級：移除該參數後重試，改以提示詞要求純 JSON，而非直接失敗。
- 每段分析結果以「影片 ID、供應商、模型、解釋語言、段落起訖時間」為鍵，快取於本機，
  重看同一部影片不會重複計費。切換供應商或模型會產生新的快取。可於設定頁一鍵清除。
- API key 僅保存在 `chrome.storage.local`，請求由瀏覽器直接送出。若不希望 key 經過瀏覽器，
  可將 `background/providers.js` 的 `ANTHROPIC_URL`、`GEMINI_URL` 指向自行架設的代理；
  代理需自行處理 CORS，或在 `manifest.json` 補上對應的 `host_permissions`。
- 以 `fetch` 直接呼叫 REST API，而非使用官方 SDK，使專案不需任何建置步驟，解壓後即可載入。
- 費用由使用者與供應商直接結算，以各供應商公告的價格為準。一般而言，「抽取單字、翻譯句子」這類任務，
  較低價的模型通常已足夠。

## 字幕取得方式

字幕向播放器取得。`captionTracks` 內的 `baseUrl` 直接 `fetch` 會回傳 HTTP 200 但內容為空，
原因是 YouTube 現在要求 proof-of-origin 權杖（網址中的 `pot` 參數）。播放器自身則能正常取得，
且其發出的請求會記錄於瀏覽器標準的 Resource Timing，因此流程如下：

1. 建立 `PerformanceObserver` 監看 `/api/timedtext`。
2. 透過播放器 API 將字幕軌切換為設定的語言（人工字幕優先，其次為自動產生）。
3. 擷取播放器發出的請求網址，其中已帶有權杖。
4. 以 `fmt=json3` 重新請求該網址，取得完整字幕與時間戳。
5. 還原使用者原本的字幕設定。

此做法只重用播放器已發出的網址，不偽造任何請求。

**必須排除帶有 `tlang` 的網址**：該參數是 YouTube 的自動翻譯，會把例如法文機器翻譯成日文，
內容看似正常但語言錯誤。切換字幕軌時，也須自行組出不含 `translationLanguage` 的軌物件。

相較於舊做法（讀取 YouTube 轉錄稿面板的 DOM），此路徑具有以下優點：

- 語言依設定決定，而非依帳號語言。
- 不需開啟 YouTube 的轉錄稿面板，沒有轉錄稿面板的影片也能使用。
- 時間戳更細（面板每行約 5–8 秒，字幕檔每行約 3–4 秒）。

轉錄稿面板僅作為備援，在播放器路徑發生暫時性失敗時使用。若影片本身沒有所需語言的字幕，
會直接回報並列出可用語言，不會退回面板。備援路徑的語言無法控制，因此所有字幕皆須通過下節的語言檢查。

## 字幕語言檢查

取得字幕後，會檢查其文字是否符合設定的學習語言（依假名、諺文、西里爾字母、漢字或拉丁字母判斷）。
不符時會暫停流程並告知偵測到的語言，**不會送往分析**，以免產生「原文與翻譯皆為中文」的結果並徒增費用。

此情況常見於「面向中文觀眾的外語教學影片」：創作者上傳多國字幕且中文排序在前，
YouTube 便依帳號語言選擇了中文。

可行的處理方式：改用沒有中文字幕的影片、將學習語言改為偵測到的語言，或按「仍要用這份字幕」強制繼續。

拉丁字母的語言（法文、西班牙文、英文等）彼此無法區分，因此不會互相誤判。

## 日文的假名標註

只標示「仕方」的單字卡，初學者無從得知讀音，記憶與查詢都會卡住。

讀音與分析結果一併取得：學習語言為日文時，schema 會多出一個 `reading` 欄位
（`background/providers.js` 的 `schemaFor()`），句子、單字與片語各自附上一串假名讀音。
其他語言不帶此欄位，以免每段多付一次 token。

模型只會回傳整串讀音（`速すぎて` → `はやすぎて`），直接標上去會變成整個詞掛著一串假名。
`LY.furigana()`（`content/lib.js`）負責切開對齊：先將表面文字切成「漢字段／非漢字段」，
非漢字的部分（送假名、助詞、片假名）在讀音中必定照抄，以其為錨點，夾在中間的即為漢字段的讀音。
漢字段的長度無法事先得知，因此由一個假名開始嘗試，交由後續的段落驗證，失敗過的位置不再重試。

```
速すぎて ＋ はやすぎて → 速(はや)すぎて
日本のお店で ＋ にほんのおみせで → 日本(にほん)のお店(みせ)で
```

對不上時一律回傳 `null`，由面板決定如何退讓：單字退回「整個詞標註一次」，句子則不標註，
因為整句掛一個 `rt` 反而更難閱讀。不含漢字的詞（外來語）本來就不標註。

假名以 `<rt>` 呈現，並在 CSS 中設定 `user-select: none`。這不僅是外觀考量：面板的「框選解說」
讀取的是 selection 的文字，假名混入後送出的句子會變成亂碼。同理，句子的原文另存於
`dataset.plain`，因為加上 ruby 之後 `textContent` 會一併輸出假名。

## 單字發音

使用瀏覽器內建的 `speechSynthesis`，不需額外權限、不連外，也沒有額外費用。
語音挑選（`LY.pickVoice()`）有兩項考量：

- **優先使用本機語音**。Chrome 部分語音為雲端合成，使用時等同將文字送往該供應商的伺服器。
- **略過 macOS 的趣味語音**。Eddy、Grandma、Bubbles 等每個語言都有一份且排序在前，不適合用於學習發音。
  若清單中只剩這類語音則仍會使用，以免完全沒有聲音。

## 面板位置

視窗寬度正常時，面板置於右側欄最上方（`#secondary-inner`）。

視窗過窄、劇院模式或全螢幕時，YouTube 會將右側欄設為 `display:none`（元素仍在 DOM 中，僅不顯示），
此時面板會自動改為右上角的浮動視窗。版面變動時會自動重新定位：監聽 `resize`，並每 2 秒檢查一次
（切換劇院模式不一定觸發 `resize`）。

圖像腳本需要 Pillow（`pip install Pillow`）。

- **圖示**：覆蓋 `store/icon-source-2000.png` 後重新執行 `make-icons.py`，`manifest.json` 無須修改。
  腳本負責兩件手動縮圖容易遺漏的事：四角去背（原圖圓角外為白色，在深色工具列上會顯示白邊），以及以 LANCZOS 縮小。
- **宣傳圖**：底圖為不含文字的插畫（`store/promo-mascot-bg.png`），文字由 `make-promo.py` 排版疊加，
  因為生圖模型在畫面中產生的文字常有錯誤。字級由演算法依版面計算，而非固定值，更動文案不致破版；
  所有尺寸皆按畫面高度換算，兩種比例共用同一套設計。
- **商店圖片格式**：須為 JPEG 或 24 位元 PNG，不得含 alpha 透明層。各腳本皆以 RGB 模式輸出並以 `assert` 檢查。

### content script 的比對範圍

`manifest.json` 中的比對範圍為 `*://www.youtube.com/*`，而非 `/watch*`，審查時須說明此點。
YouTube 是單頁應用程式：自首頁點進影片不會重新載入頁面，若僅在 `/watch` 注入，從首頁進入的使用者將不會載入指令碼。
`app.js` 依賴 `yt-navigate-finish` 事件換頁，其前提是指令碼已先載入。
因此比對範圍涵蓋整個網站，但只在 `/watch` 頁面上實際運作。

## 已知限制

- **影片須有字幕**（自動產生字幕亦可）。沒有字幕的影片無法分析。
- 自動字幕沒有標點，且偶有辨識錯誤。模型會重新斷句並修正明顯的錯誤，但不保證完全正確。
- 字幕時間戳以「行」為單位，因此段落長度只能逼近設定值，而非剛好 30 秒。
  單句播放以字數比例將一行的時長分配給行內的各句，屬估計值；語速不均時，起點可能偏差一至兩秒。
- YouTube 的 DOM 會變動，轉錄稿面板的元件名稱已更換過多次。若備援路徑失效，主要需修改
  `content/transcript.js` 開頭的選擇器。
- 僅支援 `www.youtube.com` 的 `/watch` 頁面，不支援嵌入式播放器與 YouTube Music。
- **假名可能標註在錯誤的位置。** 沒有字典就無法驗證，只能依賴「非漢字部分照抄」來對齊：
  句尾恰好是漢字時，模型多給的讀音會被該漢字吸收（`注文の仕方` 配上 `ちゅうもんのしかたです`
  會標成 `仕方(しかたです)`）。代價僅是多顯示幾個假名。讀音本身是否正確亦取決於模型，
  熟字訓與人名最容易出錯。
- 單字的 🔊 為合成音，可用語音由作業系統決定。未安裝該語言語音的電腦按下後不會發聲，
  此時按鈕的提示文字會改為「此電腦未安裝此語言的語音」。
- 模型的汰換週期短。若 Gemini 回傳 404，請於設定頁改選其他模型。
- 端對端流程（字幕取得、切段、分析、複習、匯出）已於 2026/11 使用真實 API key 在真實 YouTube 頁面上驗證。
